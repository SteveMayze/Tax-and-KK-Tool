# ADR 0034: PDF export of reports, with a signature block on the tax information summary

Status: accepted (Phase 33, 2026-10-25). Read-only reporting change: no model, migration, import or calculation changed; nothing is stored. The German wording of the notice is proposed by Claude and awaits the owner's review (`docs/glossary.md` section B).

## Decision
- **Library: reportlab 5.1.0** (BSD licence), pure Python, so no system libraries and no change to the `Containerfile` or the Ansible/Podman deployment; only `requirements.txt` gains `reportlab`, `pillow` and `charset-normalizer` (its two dependencies, all pinned). It creates AcroForm text fields and repeating table headers, and a two-pass canvas gives "Page x of y". Rejected: WeasyPrint (needs Pango and other system packages in the image, cannot create fillable fields), print-CSS only (no fillable fields; the `@page` landscape stylesheet for the HTML page was skipped), fpdf2 (weaker tables and forms).
- **Route:** `/reports/<key>.pdf` with the same parameters, validation, error message and redirect as the CSV (`_build`), login required, GET only, `Cache-Control: no-store`, `nosniff`, built in memory and streamed. File name `report-<key>-<year or all>[-filtered].pdf`, language-independent.
- **No figures in the PDF layer:** `report_pdf.render` receives the finished `Report` and the same display cells as the HTML page (`_display`), so page and PDF cannot differ. It follows the interface language (the CSV does not).
- **Layout:** landscape A4, title, generated date, basis block before the table, repeating header row, totals row, notes after the table, a footer on every page with "Page x of y" and the one-line "General financial summary, not an official assessment or tax calculation". Column widths follow the widest cell; the font shrinks with the column count (8, 7 or 6 pt).
- **Tax information summary only:** a boxed notice near the title and again above the signature block (kept together on the last page; the table itself may split), then three lines: Place (Ort), Date (Datum), Signature (Unterschrift), bilingual in English mode, German term alone in German mode. Place and date are real AcroForm text fields; the signature is a blank box with a real signature field (`/FT /Sig`, added with pypdf because reportlab has no API for it), so Preview and Acrobat can sign it; printed, it can be signed by hand. Nothing is pre-filled and the document author metadata is empty.
- **Fonts:** the built-in Helvetica (WinAnsi), which covers German letters and the euro sign; no font files are bundled. A character outside it would print as a blank box.

## Consequences
The PDF is a rendering for reading and signing, not an archive format. The notice text is legal-adjacent wording and must be reviewed by the owner before the PDF is relied on.

## Addendum (Phase 34, 2026-10-25): compact signature block with a Name field
- **Layout (revised the same day after reviewing the first result):** one left-aligned column, at most one third of the usable width (`COLUMN_FRACTION = 1/3`, about 92 mm), in three rows: **Name** (fillable, full column width); **Place (Ort)** and **Date (Datum)** side by side under it, sharing the column width equally with a 6 mm gap (`GAP`), so the pair ends where Name ends; **Signature (Unterschrift)** under both, full column width, 14 mm tall (`SIGN_H`). All three rows share the same left and right edges. Name, Place and Date are single-line height (7 mm). Each label sits above its line; the constants are in `core/services/report_pdf.py`. At the 11 pt field font, "Frankfurt am Main" and "25.10.2026" fit the roughly 43 mm Place and Date fields (asserted in a test), so no widening was needed.
- **Fields:** text fields `name`, `place`, `date` and the `/Sig` field `signature`, created and listed in that order, so the tab order is Name, Place, Date, Signature. Nothing is pre-filled. Printed, the lines and the box can still be filled in by hand.
- **Page break:** the notice and the whole block are one `KeepTogether` group: they follow the table on its last page when they fit under it, otherwise they move to the next page together, never split. The last table rows are **not** pulled along: reportlab cannot split a table to keep a few rows with a later flowable, so the simple rule was kept. In the synthetic sample the table fills page 1, so the group sits on page 2 with the notes.
