# ADR 0025: Joint account routing and matching rules

Status: accepted (Phase 25, 2026-10-20; the owner's questions Q25.1 to Q25.3 were answered by their stated defaults).

## Context
The household joint account is at the same bank, with the same layout, as the Phase 17 account. `rvb_account` recognises by structure only, so it already claimed these files and would have reported "nothing to import" for statements whose job is different (rent paid straight from the tenant). The joint account is a household account: most bookings are not rental, so "an unknown booking text refuses the statement" (ADR 0017) cannot apply. What counts as rent differs by tenant and changes over time, and no tenant or institution name may be in code.

## Decisions
1. **Identity by account number.** The setting `DJANGO_JOINT_RENTAL_ACCOUNT` (digits only; a value that is not digits stops start-up without echoing it) is compared digit for digit with the account number printed on the statement (`rvb_joint.account_number`). It is never stored, logged or shown unmasked (`mask_account`: at most the last two digits). Empty = the new reader claims nothing and nothing changes for any file.
2. **Exactly one reader claims a file (J1).** `rvb_joint` (id `rvb_joint`, layout mode) claims a file with the balance rows and that account number; `rvb_account.recognises` returns False for that account only, otherwise exactly as before (its tests and the 23 real files are unchanged).
3. **Grammar and arithmetic only refuse a statement (J2).** Every booking line must parse; the page carries ("Übertrag auf Blatt n" / "Übertrag von Blatt n-1") must agree with the running balance and each other; alter + credits - debits = neuer. Refusal names page and booking position, never figures. A line that parses and matches no rule is simply not rental. The printed value date may be a non-date ("30.02.": the bank uses 30-day months for interest and charges); it is not needed and becomes empty instead of refusing the statement. Fixed words are matched tolerantly of letter-spacing (J17).
4. **Rules are data.** Model `StatementRule` (label, kind `tenant_rent` | `service_charge_settlement`, direction credit, pattern, match_on counterparty | purpose | either, organisation, valid_from/valid_to, active), edited in the Django admin (the only editing area that exists; it needs `DJANGO_ENABLE_ADMIN=1` outside development). No migration seeds a rule. The model validates the pattern on save: invalid and empty-matching patterns are rejected, an income rule needs an organisation.
5. **Matching on normalised text (J4).** Text and pattern are compared in two forms: umlauts expanded (ü to ue, ß to ss) and umlauts reduced to the bare letter, diacritics removed, case-folded, hyphens as spaces, spaces collapsed. "Jürgen Köhler", "JUERGEN KOEHLER" and "Juergen Koehler" normalise to one string; a bare-vowel spelling matches through the second form.
6. **Conflict (J11).** A credit matching rules of different kinds, or of the same kind for different organisations, is a conflict: it is never staged and the statement gets a notice. (Different organisations are treated as a conflict beyond the phase text: attributing a credit to one of two tenants would be a guess.)
7. **Preview.** `tools/rule_preview.py <folder>` prints per rule (by id and kind only: no label, pattern, name or amount) how many credit lines match and in which statements (printed number/year), and how many lines match more than one rule and how many of those conflict.
8. **Skeleton reader.** `parse` proves the statement and returns no rows (nothing to import). Fingerprint = reader, statement number, year, closing balance (J22). Continuity (balances and dates) is supplied now for Phase 26's chain check. The reader loads the active rules from the database (a documented deviation from "readers know nothing about the database"; needed by the rule matching of Phase 26).
9. **Category setting** `DJANGO_JOINT_RENTAL_CATEGORY` (default `Rental (joint)`) exists; the importer never creates it. Its use, and the explanation when it is missing, arrive with the rows in Phase 26.

## Consequences
All 21 real joint-account statements (December 2024 to September 2026) are read with none refused and a gapless chain (checked locally, counts only). Open rules item: how shared rent is treated for the tax return and for SBK is not decided (rules README item 22, unverified).
