# ADR 0013: Visual refresh, button rules, report layout and information popups

Status: accepted (Phase 13, 2026-10-19; owner answers: no dark mode; payment list and reports are polished first; the basis block stays with the report table).

## Decisions
1. **Design tokens.** One stylesheet, `core/static/core/base.css`, with CSS variables in `:root` (blue/teal palette: teal primary, deep blue headings and focus ring, neutral greys, success/warning/danger colours). Colours appear only as tokens (a test enforces it). `tools/check_contrast.py` lists the text/background pairs and requires 4.5:1 for text and 3:1 for control borders; a test runs it. No dark mode.
2. **No inline styles.** Templates use classes (`total-row`, `row-excluded`, `narrow`); a test checks the rendered main screens in both languages for `style=`.
3. **Buttons.** `.btn` styles (primary teal, secondary, danger) for actions: add, edit, save, cancel, export (CSV), recalculate, delete. Plain links remain for navigation. Anything that changes or deletes data is a POST `<form>` with a `<button>` and a CSRF token. "Delete" and "Recalculate" in lists are links *to a confirmation page* (a GET that changes nothing); the data change happens only on that page's POST button, so the confirmation required by CLAUDE.md stays. A test proves that a GET never deletes or recalculates and that the POST-only actions answer 405 to GET.
4. **Inputs.** Text inputs are at least 20 characters wide (names and descriptions wider), selects, dates and text areas share one height and border. Note and description fields (payment comment, year notes, annual-input note, rate reasons, import comment) are text areas of 4 rows that grow with their content (CSS `field-sizing`, with `core/static/core/autosize.js` as a fallback). `AnnualInput.note` changed from 300 characters to a text field (migration 0009); the payment comment was already unlimited.
5. **Report layout.** The basis block stays directly above the table; the report's descriptive notes moved below the table and its totals. Verified by a test on the rendered HTML for every report.
6. **Information popups.** Each of the 14 SBK column headings has a real `<button type="button">` with an accessible name ("Information: <heading>") that opens a native Popover API element (`popover` attribute), so it needs no JavaScript, is reachable by keyboard and closes with Escape. The content is the glossary entry in the selected language, with source and status. The text lives in `core/glossary.py` (needed at run time: the image has no `docs/`); a test fails if it differs from `docs/glossary.md` section A, which gained a German explanation column. Browsers without Popover support show the button but no popup (the heading text is unchanged).
7. **CSV and print.** CSV exports are built from the report data and never contain icons or popups (tested). The print stylesheet hides navigation, buttons and info icons and keeps the table, the basis and the notes below it.

## Not verified here
No browser was driven: the pages were checked as rendered HTML (structure, classes, attributes) and the colours by the contrast script. Escape-to-close is the platform behaviour of an auto popover and is not simulated.
