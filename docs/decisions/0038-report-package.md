# ADR 0038: PDF package with the originating documents

Status: accepted (Phase 42, 2026-11-04). Read-only: no model, migration, stored file, batch or payment changes; `UPLOAD_DIR` gains no file. German wording is proposed, awaiting the owner's review.

## Decision
- **Form (Q42.1): a ZIP** `report-tax_summary-<year or all>[-filtered]-package.zip` holding the report PDF (the same bytes-producing path as `/reports/tax_summary.pdf`, same parameters and interface language), `sources/<reference>_<masked name>.pdf` (originals copied byte for byte), `index.csv` (English headings: reference, file name in the package, file name as displayed, SHA-256, size, state, payments in the report) and a short `README.txt` (English or German, no figures). Only statements referenced by the selected payments are included; CSV batches never are (Q41.2). Not built: one merged PDF with bookmarks, or attachments embedded in the report PDF. Both change the originals' form (a merged file is no longer the statement; embedded files depend on the viewer and are often stripped or flagged by mail and adviser software). The ZIP keeps every original verifiable against its hash.
- **Hash check:** each original is hashed before it is copied and must equal the recorded hash (a single PDF: the batch hash; a zip member: the hash computed when the reference was resolved, and the stored zip as a whole must still equal the batch hash, otherwise a changed member could pass). A mismatch is "changed on disk, not included", listed in `index.csv` and on the confirmation page. A missing or removed original is listed and the package is still built.
- **Entry (Q42.2):** a button "PDF with source documents" on the report page opens a confirmation page (GET, login required, reads only): statements included, their total size, those not included with the reason, the active filter, a plain warning that the statements contain account numbers and other personal data and that the package is unprotected once downloaded; then "Download package" or "Report PDF only". No document text, unmasked digit run or stored path is shown. Download route: `Cache-Control: no-store`, `nosniff`, `Content-Disposition: attachment`; with nothing to package it redirects back to the confirmation page, never an empty zip.
- **Size limit (Q42.3):** `DJANGO_REPORT_PACKAGE_MAX_MB` (default 100), compared with the total size of the included originals; above it no package is offered and the report-only link remains. The zip is built in an anonymous temporary file (`tempfile.TemporaryFile`), streamed with `FileResponse` and gone when closed, also after an interrupted download or a failed build. In the container `/tmp` is a tmpfs (`Tmpfs=/tmp`), so it counts against the 512 MB memory limit: the default of 100 MB leaves room, and a larger limit should be set together with a larger memory limit.
- **Names (Q42.4):** generated here from the reference and the masked display name with every character outside `A-Za-z0-9._# -` replaced, at most 80 characters, one path level; the reference keeps names unique. The hashes in `index.csv` let the owner match files to the unmasked originals.

## Consequences
Building reads each stored original twice (hash, then copy), and each stored zip once more as a whole. For the 2025 development data (44 statements, about 40 MB) this took under a second. The package contains personal data: the owner must check it before handing it on.
